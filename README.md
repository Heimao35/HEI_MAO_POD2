# 视频播放使用指南

本项目的 ESP32-P4 多媒体播放器支持播放 460×460 的裸 MJPEG 视频，并可选择
播放同名 WAV 音轨。本文说明文件组织方式、导出命令、可选的帧位置索引、播放器
操作以及常见问题。

## 1. 支持范围

- **视频**：460×460、8bit、三分量 baseline JPEG 连续拼接的裸 `.mjpeg` /
  `.mjpg` 文件。不支持 MP4、MKV、AVI 等容器文件。
- **帧率**：24 / 30 / 60fps。由视频（文件夹）名称中的 `24fps`、`30fps`、
  `60fps` 标记决定；没有标记时按 60fps 处理。
- **音频（可选）**：与视频同名的 WAV。只支持 PCM 16/24/32bit、单/双声道，
  采样率 32k/44.1k/48k/88.2k/96k/176.4k/192k；推荐 48kHz/16bit 立体声。
  不做音频解码，MP3/AAC/浮点 WAV 等不支持，没有音轨时静音播放。
- **文件上限**：FAT32 单文件最大 4 GiB−1。SD 卡建议格式化为 FAT32 并使用
  32/64 KiB 簇，以保证视频顺序读取吞吐。

## 2. 目录结构

每段视频放在一个与其同名的文件夹中：

```text
HEI_MAO_POD_SYS/MEDIA/video/
  秒速五厘米_24fps/
    秒速五厘米_24fps.mjpeg    视频（必须与文件夹同名）
    秒速五厘米_24fps.wav      可选音轨（同名）
    秒速五厘米_24fps.vix      可选帧索引（见第 4 节）
  言语之庭_24fps/
    言语之庭_24fps.mjpeg
    言语之庭_24fps.wav
```

规则：

- 视频列表显示的名称就是文件夹名；
- `.mjpeg` / `.mjpg` 文件名必须与文件夹名一致；`.wav` 可选；
- 帧率标记写在文件夹名里，例如 `名字_24fps`、`名字_30fps`、`名字_60fps`；
- 旧式平铺文件 `MEDIA/video/xxx.mjpeg` 仍然兼容，但没有音轨和索引，
  拖动只能按文件大小比例估算。

## 3. 导出视频与音轨

使用 ffmpeg 分别导出视频和音轨（示例为 24fps）：

```bash
ffmpeg -i input.mp4 -vf scale=460:460 -r 24 -q:v 1 -an "秒速五厘米_24fps.mjpeg"
ffmpeg -i input.mp4 -vn -acodec pcm_s16le -ar 48000 -ac 2 "秒速五厘米_24fps.wav"
```

- 视频必须是 baseline JPEG；ffmpeg 的 mjpeg 编码器默认输出 baseline。
- `-r` 的帧率必须与文件夹名中的 `24fps/30fps/60fps` 标记一致。
- 音轨要与视频来自同一源、同一时间段；`-ac 2` 强制双声道，避免源音频是
  多声道导致 WAV 不被支持。
- 导出后按第 2 节建立同名文件夹，把文件放进去。

## 4. 精确拖动：可选的 `.vix` 帧索引

裸 MJPEG 没有逐帧时间戳，而且通常是变码率。**没有索引时**，拖动进度条只能
按“文件大小比例”估算时间，音轨却按“时间比例”定位，变码率视频拖动后可能
音画不同步；**连续播放不受影响**（始终以音频实际播放时间为主时钟）。

`.vix` 是一份很小的稀疏帧位置表（1 小时 24fps 约 15 KB），由 PC 端工具用
ffprobe 一次性生成，放在视频同目录、同主文件名。生成后在设备上拖动会按
“时间 → 帧号 → 字节偏移”精确定位，音画误差不超过 1 帧。

在项目根目录执行：

```bat
python scripts\mjpeg_index.py "路径\秒速五厘米_24fps.mjpeg"
```

- 帧率自动从文件名中的 `24fps/30fps/60fps` 识别；没有标记时加 `--fps 24`；
- `ffprobe` 不在 PATH 时，用 `--ffprobe "D:\...\ffprobe.exe"` 指定；
- 默认每秒一个检查点，可用 `--interval 0.5` 提高精度（索引相应变大）；
- 输出 `秒速五厘米_24fps.vix`，与视频、音轨一起放进 SD 卡文件夹。

设备播放时会打印 `video_index: Index: ... checkpoints`，表示索引已加载。
视频重新导出后必须重新生成索引；固件会用文件大小校验，索引与视频不匹配时
自动忽略并回退到原来的字节比例行为，不会播放错乱。

## 5. 播放器操作

- 视频首页每页 2×2 四个预览图，预览取视频中间的一帧；左右滑动翻页；
- 点击预览立即全屏播放，并自动暂停正在播放的音乐；
- 全屏播放覆盖状态栏，仍可从屏幕边缘唤出模式选择栏和声光控制栏；
- 点击画面显示/隐藏控制台，3 秒无操作后控制台自动渐变隐藏；
- 底部为返回键、播放/暂停键和可拖动的进度条；
- 播放中左右滑动切换上一个/下一个视频（带切换动画）；
- 退出视频模式、锁屏、关机时自动停止播放并把音频通道归还给音乐；
- 播放视频时，物理音量键、静音控制同样作用于视频音轨。

## 6. 音频与同步说明

- 有音轨时以音频实际播放时间为视频主时钟，连续播放不会累积漂移；
- 拖动后是否精确对齐取决于 `.vix`：有索引误差不超过 1 帧；没有索引时按
  相同文件比例估算，变码率文件可能有偏差；
- WAV 比视频短：剩余画面会自动回退到计时播放；WAV 更长则在视频结束时停止；
- 耳机拔出会暂停视频音频，画面同步暂停；重新插入不会自动恢复播放；
- 音频格式不支持时（例如浮点 WAV、多声道），视频静音播放并在串口说明原因。

## 7. 常见问题

**提示“无法打开视频文件”或“帧解码失败”**

- 视频不是 460×460 baseline JPEG，或分辨率/分量数不符合要求；
- 文件超过 FAT32 的 4 GiB−1 上限；
- SD 卡簇过小或读取超时，可重新格式化为 32/64 KiB 簇。

**视频没有声音**

- 确认 WAV 与视频在同一个文件夹、主文件名相同、扩展名为 `.wav`；
- 确认是 PCM 编码（`pcm_s16le/pcm_s24le/pcm_s32le`），可用
  `ffprobe -show_streams 名字.wav` 查看；
- 串口出现 `Video audio unavailable` 表示格式或通道配置失败，此时会静音播放。

**拖动进度条后音画不同步**

- 缺少 `.vix`，或视频重新导出后没有重新生成索引。按第 4 节生成后重新进入播放。

**拖动失败/提示“无法跳转”**

- 索引与视频内容不一致时会自动回退；仍失败请检查 SD 卡是否可读、
  播放过程中是否拔出过卡。目标位置超出文件末尾也会失败。

**播放卡顿**

- SD 卡建议 FAT32、32/64 KiB 簇；串口 `Video: xx decoded fps` 可查看实际帧率，
  `Video PCM: ... underrun=...` 持续增长说明音频供给不足。

**索引生成失败**

- `ffprobe` 不在 PATH，用 `--ffprobe` 指定完整路径；
- 文件名不含帧率标记，用 `--fps 24/30/60` 指定。

## 8. 相关日志

| 日志 | 含义 |
|---|---|
| `WAV: ... frames` | WAV 解析成功 |
| `Video audio: ...` | 音轨已交给 DAC 通道 |
| `Video PCM started: ...` | 音频开始输出 |
| `Video PCM: queued=... sent=... underrun=...` | 每 5 秒音频健康状态 |
| `video_index: Index: ... checkpoints` | 帧索引已加载 |
| `Seek index does not match the video` | 索引失效，已回退字节比例 |
| `Video: ... decoded fps (target ...)` | 每 5 秒视频解码统计 |
