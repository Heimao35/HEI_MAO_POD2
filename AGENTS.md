# Project memory and maintenance rules

- ESP32-P4 multimedia player: 32 MB PSRAM and 32 MB Flash; ESP-IDF v5.5.4.
- Preserve existing UI layout, gestures and animation behavior unless the user explicitly asks to change them. Add detailed comments to UI-related changes. Charging indicators remain gold; the normal UI palette is white.
- PMIC is AXP2101. SDA = GPIO48, SCL = GPIO47, IRQ = GPIO10; 7-bit I2C address = 0x34. Touch already uses I2C0 on GPIO7/8; the PMIC uses I2C1.
- Read `docs/PMIC_AXP2101.md` before changing power management. It records the user's wiring, datasheet register mappings, power limits, implementation scope and verification status.
- DCDC4 can be set to 1.8 V; ALDO3 can be set to 3.3 V but is rated at only 300 mA, below Espressif's >=500 mA ESP32 supply recommendation. Do not silently treat the LDO's protection current as its output rating.
- Authorized PMIC work includes fuel-gauge/VBUS/charging monitoring, the larger status-bar battery icon, and startup power for DCDC4=1.8 V (DAC) and ALDO3=3.3 V (ESP32-U4WDH). Verify both voltage fields before enabling outputs, preserve unrelated register bits, and do not power-cycle already-configured rails during monitoring retries. Other rails, charging current/voltage, battery model and hardware power-key policy remain unchanged unless requested.
- PMIC IRQ is active-low/open-drain. Keep blocking I2C and file access outside GPIO ISRs and the LVGL lock. Publish UI state while holding the LVGL lock. Unknown battery data must not be replaced by a demo percentage.
- User bench feedback (2026-10-18): DCDC4, ALDO3 and RTC supplies work. No exact RTC voltage or radio-load measurements were provided. AXP2101 soft shutdown is reg0x10 bit0 (bit1 restarts); RTCLDO is retained. Long-press shutdown and the NVS settings snapshot are now implemented; lock-screen Light-sleep remains separate. See docs/PMIC_AXP2101.md before changing power behavior.

- Lock-screen power work authorized (2026-10-18): lock page idles for 10 s, or receives another short PWRON press while visible, then fades brightness to zero over 300 ms and pauses LVGL plus physical DPI DMA refresh. Touch IRQ=GPIO6 (CST820 reset=GPIO5) and PMIC IRQ=GPIO10 wake to the existing lock page with MJPEG replayed from its first frame, without a page slide; awake short PWRON press enters the lock page using the existing top-down ease-out curve. Consume the wake touch rather than unlocking with it.
- `screen_power.c` owns screen-off/wake and explicit bounded Light-sleep when not playing, with JPEG/SD/PMIC quiescence guards. Keep touch/PMIC/PSRAM powered. Never substitute Deep-sleep or PMIC poweroff for this lock. GPIO6/10 use EXT1 ANY_LOW; after every Light-sleep return, call rtc_gpio_hold_dis on both pins before rtc_gpio_deinit to return to digital GPIO. The current media adapter is metadata-only and reports no real active audio output yet.
- The v5.5.4 DPI suspend/resume extension is generated into `build/player_display` by `scripts/display_sleep.cmake`/`patch_dpi_sleep.py`; do not edit installed SDK or managed files. Review the extension before any SDK upgrade. Wake resets the bridge FIFO/Host scan state, restores bridge configuration and the selected framebuffer, then waits for two fresh physical VSYNC events before lighting the panel. This requires the configured P4 minimum revision >=3.0. User feedback reports the wake-alignment fix works; extended repeated wake/display stability, touch IRQ pulse capture and board power consumption still need bench testing.

- Physical volume keys (2026-10-18): volume up GPIO35, down GPIO34. Implementation assumes active-low contacts to GND, with internal pull-ups; polarity is centralized in `volume_keys.c` and awaits board confirmation. 30 ms debounce, +/-5 per press, 400 ms hold then 100 ms repeat; both keys together are ignored until released. Keys do not add screen-off wake sources.
- Hardware volume uses `ui_adj_panel_adjust_volume()` under the LVGL lock: reuse the existing volume slider/mute control in a narrow column, hide brightness and the full-screen overlay, retain the original ease-out slide, pass blank-area touches to underlying pages, and auto-hide after 5 s without volume interaction (never during dragging). Gesture opening retains the original two-column modal panel/mask. Only `ui_adj_panel_is_modal()` blocks page gestures. The audio callback is still NULL until a real DAC volume backend is connected.
- Volume validation: ESP-IDF v5.5.4 firmware builds; UI host tests 8/8 pass, including GPIO debounce/repeat, non-modal hit tests, real slider drag, inactivity/reopen and existing player gestures. Actual volume-key polarity, repeat feel and board behavior remain to be verified.

- Long-press shutdown/persistence is implemented in `main/system_power.c`, `main/player_settings.c` and `main/ui/ui_power_dialog.c`; `docs/POWER_OFF_PERSISTENCE_PLAN.md` records extension points. AXP2101 OFFLEVEL is configured to 10 s and hardware poweroff remains the crash-safe fallback. An independent EEPROM is not identified; current persistence uses the existing Flash NVS partition. Do not silently add another backend.

- Shutdown/NVS authorization (2026-10-18): user explicitly wants 6 s PWRON prompt (confirm shutdown/restart/cancel), with 10 s continuous hold independently forcing AXP2101 hardware poweroff even if software crashes. Configure/verify reg0x27[3:2]=11b and reg0x22[1:0]=10b; preserve unrelated fields. IRQ masks now D0/FB/18 (short/down/up; long IRQ remains disabled). Cancel never disables hardware hold-off.
- `system_power.c` coordinates bounded media/JPEG quiescence, display fade/suspend, NVS commit+reopen/readback and PMIC-owner soft poweroff; restart now uses the PMIC owner to issue reg0x10 bit1 for system POWOFF/POWON, clearing bit0 and preserving other bits; never fall back to P4 `esp_restart()`. Failure restores screen/media and leaves retry/cancel available. Normal lock-screen Light-sleep is unchanged. Media pause/BUSY ownership shares an atomic state word for SMP handoff.
- `player_settings.c` uses existing NVS `player/settings`, bounded versioned TLV+CRC blob (<=1KiB); saves user brightness, volume, muted/auto-brightness flags and stable music folder/audio filename. No playback-time restore or auto-play. Background save coalesces after 3 s, identical snapshots skip Flash writes; normal shutdown flushes before the terminal action. New fields require codec, snapshot, equality and restore updates; do not serialize raw structs or erase NVS automatically on errors/unknown versions. Forced poweroff can lose uncommitted changes.
- Shutdown verification: firmware builds and host CTest 10/10 pass. Hardware 6/10 s timing, VBUS soft-off behavior, reboot/retention, cut-power recovery and sustained load remain untested; do not infer them from host doubles.

- Boot-key/first-sleep fixes (2026-10-18): consume the initial successfully ACKed PMIC key-status snapshot without callbacks; never reset that baseline on ordinary monitor retries. `system_power` ignores key events before its init completes and requires a fresh down/up pair before delivering a short action. Do not replay the key used to power on as lock-screen off. User reports of spontaneous first wake/slow key response match a missing RTC pad HOLD release; source omission is confirmed, full physical root cause remains to bench-test. Host sleep model enforces hold-dis-before-deinit; PMIC tests verify reg0x10[1] restart keeps 10s forced-off policy.

- Touch wake filtering (2026-10-18): user confirms earlier boot-key/PMIC restart/key-delay issues resolved but reports both key-off and idle-off still auto-wake. Treat GPIO6 IRQ/low and EXT1 touch flags only as candidates. `screen_power.c` reads fresh CST820 data outside ISR/LVGL/SD locks while LVGL input is disabled; only valid nonzero in-bounds touch points may cancel fade/resume DPI. Empty hints, stale cached coordinates and I2C errors keep screen dark. Explicit software/PWRON wake is a separate event and must not require a working touch chip. Notify the power task immediately on IRQ/RTC/software events to preserve short taps; retain candidates deferred by the 20ms probe bound. Sustained low without contact stays black and defers Light-sleep rather than self-notifying in a busy loop. Host tests cover these cases. User subsequently reports all current behavior normal after testing (2026-10-18); electrical origin of empty touch hints, long-duration reliability and measured sleep current remain unverified.

- User bench acceptance (2026-10-18): after the final touch-candidate validation fix, user reports “一切正常” and authorizes committing the current shutdown/NVS/PMIC restart/wake changes. This is functional feedback, not a measurement of rail waveforms, sleep current, forced-crash recovery or NVS cut-power resilience.
