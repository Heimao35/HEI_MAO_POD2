# Project memory and maintenance rules

- ESP32-P4 multimedia player: 32 MB PSRAM and 32 MB Flash; ESP-IDF v5.5.4.
- Preserve existing UI layout, gestures and animation behavior unless the user explicitly asks to change them. Add detailed comments to UI-related changes. Charging indicators remain gold; the normal UI palette is white.
- PMIC is AXP2101. SDA = GPIO48, SCL = GPIO47, IRQ = GPIO10; 7-bit I2C address = 0x34. Touch already uses I2C0 on GPIO7/8; the PMIC uses I2C1.
- Read `docs/PMIC_AXP2101.md` before changing power management. It records the user's wiring, datasheet register mappings, power limits, implementation scope and verification status.
- DCDC4 can be set to 1.8 V; ALDO3 can be set to 3.3 V but is rated at only 300 mA, below Espressif's >=500 mA ESP32 supply recommendation. Do not silently treat the LDO's protection current as its output rating.
- Authorized PMIC work includes fuel-gauge/VBUS/charging monitoring, the larger status-bar battery icon, and startup power for DCDC4=1.8 V (DAC) and ALDO3=3.3 V (ESP32-U4WDH). Verify both voltage fields before enabling outputs, preserve unrelated register bits, and do not power-cycle already-configured rails during monitoring retries. Other rails, charging current/voltage, battery model and hardware power-key policy remain unchanged unless requested.
- PMIC IRQ is active-low/open-drain. Keep blocking I2C and file access outside GPIO ISRs and the LVGL lock. Publish UI state while holding the LVGL lock. Unknown battery data must not be replaced by a demo percentage.
- User bench feedback (2026-10-18): DCDC4, ALDO3 and RTC supplies work. No exact RTC voltage or radio-load measurements were provided. AXP2101 soft shutdown is reg0x10 bit0 (bit1 restarts); RTCLDO is retained. Software shutdown remains unimplemented; lock-screen Light-sleep is described below; see docs/PMIC_AXP2101.md before designing lock/shutdown/wakeup behavior.

- Lock-screen power work authorized (2026-10-18): lock page idles for 10 s, or receives another short PWRON press while visible, then fades brightness to zero over 300 ms and pauses LVGL plus physical DPI DMA refresh. Touch IRQ=GPIO6 (CST820 reset=GPIO5) and PMIC IRQ=GPIO10 wake to the existing lock page with MJPEG replayed from its first frame, without a page slide; awake short PWRON press enters the lock page using the existing top-down ease-out curve. Consume the wake touch rather than unlocking with it.
- `screen_power.c` owns screen-off/wake and explicit bounded Light-sleep when not playing, with JPEG/SD/PMIC quiescence guards. Keep touch/PMIC/PSRAM powered. Never substitute Deep-sleep or PMIC poweroff for this lock. GPIO6/10 use EXT1 ANY_LOW and return to digital GPIO after each wake. The current media adapter is metadata-only and reports no real active audio output yet.
- The v5.5.4 DPI suspend/resume extension is generated into `build/player_display` by `scripts/display_sleep.cmake`/`patch_dpi_sleep.py`; do not edit installed SDK or managed files. Review the extension before any SDK upgrade. Wake resets the bridge FIFO/Host scan state, restores bridge configuration and the selected framebuffer, then waits for two fresh physical VSYNC events before lighting the panel. This requires the configured P4 minimum revision >=3.0. User feedback reports the wake-alignment fix works; extended repeated wake/display stability, touch IRQ pulse capture and board power consumption still need bench testing.

- Physical volume keys (2026-10-18): volume up GPIO35, down GPIO34. Implementation assumes active-low contacts to GND, with internal pull-ups; polarity is centralized in `volume_keys.c` and awaits board confirmation. 30 ms debounce, +/-5 per press, 400 ms hold then 100 ms repeat; both keys together are ignored until released. Keys do not add screen-off wake sources.
- Hardware volume uses `ui_adj_panel_adjust_volume()` under the LVGL lock: reuse the existing volume slider/mute control in a narrow column, hide brightness and the full-screen overlay, retain the original ease-out slide, pass blank-area touches to underlying pages, and auto-hide after 5 s without volume interaction (never during dragging). Gesture opening retains the original two-column modal panel/mask. Only `ui_adj_panel_is_modal()` blocks page gestures. The audio callback is still NULL until a real DAC volume backend is connected.
- Volume validation: ESP-IDF v5.5.4 firmware builds; UI host tests 8/8 pass, including GPIO debounce/repeat, non-modal hit tests, real slider drag, inactivity/reopen and existing player gestures. Actual volume-key polarity, repeat feel and board behavior remain to be verified.
