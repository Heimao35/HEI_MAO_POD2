# SD 音乐浏览接入（无 DAC 阶段）

## 本阶段范围

实现 SD 卡扫描、真实歌曲列表、选歌、封面解码显示、LRC 滚动浏览、基础音频文件信息。
**没有接入音频解码、PCM 输出或 DAC；播放按钮不会伪造播放状态/播放进度。**
歌词支持手动滚动和两秒无操作后按后端时间回跟；当前后端时间为 0，真实音频时钟尚未接入。

## 文件布局

```text
SD 卡根目录/
└── HEI_MAO_POD_SYS/
    ├── MUSIC/
    │   ├── 歌曲文件夹A/
    │   │   ├── 歌曲A.flac
    │   │   ├── 歌曲A.jpg
    │   │   └── 歌曲A.lrc
    │   └── 歌曲文件夹B/
    │       ├── 歌曲B.mp3
    │       ├── 歌曲B.jpg
    │       └── 歌曲B.lrc
    └── .hmcache/
        └── music.idx       # 程序生成的临时性索引，不要手工编辑
```

- 每个一级子文件夹代表一首歌曲，标题取文件夹名；不递归扫描。
- 音频和两个附件的文件主名应一致，但不要求与文件夹名相同。
- 支持 `.flac` / `.mp3`、`.jpg`、`.lrc`；ASCII 大小写不敏感。
- 一个目录误放多个音频时，只选文件名字节序最小的一个，附件按该文件主名匹配。
- 缺封面/歌词仍保留歌曲；封面留空，歌词显示原有提示，不会导致整首歌曲消失。
- 文件名/目录名上限为 255 个 UTF-8 **字节**，不是 255 个汉字；超长名称不截断使用。
- 歌曲顺序为文件系统的目录枚举顺序，暂未做全库排序。

## 使用方式

1. 开机或插卡成功后后台自动扫描；扫描结束自动加载第一首歌曲。
2. Open the playlist with the original list button or upward gesture; all scanned songs are drawn and the page remains vertically scrollable.
3. 点击歌曲、上一首/下一首按钮或左右滑动切换歌曲。
4. 点击封面区域以 70ms 淡出、90ms 淡入切换封面/歌词；两段之间不额外等待。仅调整 Canvas 图片和 Label 文字透明度，复用现有对象和缓存，不新增中间图层。连续点击从当前透明度转向最新目标；切歌或重建曲库立即结束淡变并恢复目标模式的完整显示。歌词透明显示在原有 240×240 视口中，不覆盖控制台，也不因切换重置滚动位置。
5. 首行歌词从视口中央开始；可上下拖动浏览，按住时不回跟，释放后两秒无操作则自动回到后端时间对应行；长句换行后仍按实际位置居中。
6. 歌词区域内的竖向拖动只滚动歌词；其他区域保留上滑展开列表、列表上边缘下滑收起，以及原有展开/收起动画。横滑切歌不再同时触发封面/歌词点击切换。
7. 重新挂载时自动重建索引。拔卡会停止两层切歌动画、清空歌曲和歌词；不增加 Rescan / Cover 等控件。
8. 原播放控制台和模式按钮保留；后端当前始终报告未播放、进度 0，不输出音频，也不模拟计时。
9. 封面顶部短歌名居中，长歌名横向滚动；列表每首一行，长歌名横向滚动。
10. 上一首/下一首沿用原单段时长和曲线，旧内容滑出与新内容滑入同时开始。动画开始即更新歌曲索引、歌名、高亮和进度，并投递加载；只有动画运动期间忽略重复切歌，不等待 SD/JPEG/LRC 完成。
11. 当前歌曲加载完成后，后台预读前后各一首封面（首尾循环，两首库去重，单首库不预读）。缓存命中时直接参与滑入；未命中或封面损坏时先留空，加载完成后原位补显，不重新启动动画。
12. 歌词模式也使用独立的滑出快照，保留上一首文字、字号、行距和滚动位置，避免加载新歌词时改写正在离屏的旧歌词。
13. 音乐页面用当前封面生成全屏模糊背景，白色混合约 15%，新背景就绪后以 180ms 交叉淡变替换。未就绪或缺封面时保留原背景，不阻塞选歌；拔卡/重扫清空背景，恢复原页面底色。背景只属于音乐页面，不接管触摸，不移动标题、歌词、控制台或列表。
14. 播放控制台取消背景，保留布局/事件容器；按键使用 20% 不透明度的白色背景；播放/单曲循环选中态提高至 40%，按下时分别为 30%/50%。进度条使用白色，时长字体由 12 号增至 16 号并保持右侧对齐，时间与图标保持清晰。状态栏全局使用 20% 不透明度的黑色背景。进度条从 6px 加粗至 8px，并右移 10px；标题、封面和歌词整体下移 16px，点击/滚动命中区域随父容器同步移动，且不与按键扩展点击区重叠。手势及动画逻辑保留。音乐控制台参数见 `ui_music_player.c` 的 `CTRL_*_BG_OPA`；状态栏参数见 `ui_common.h` 的 `UI_STATUSBAR_BG_*`。

封面请导出为 **240×240 的普通非渐进式 JPG**，最大 256 KiB；尺寸不匹配或硬件解码失败时封面留空。
LRC 请保存为 **UTF-8**，支持 BOM、CRLF、多时间标签、1/2/3 位小数、`offset` 和乱序时间标签排序。
UTF-16/非法 UTF-8 会提示转为 UTF-8。非时间元信息标签不参与歌词内容。
配置已编译 LVGL 内置 Source Han Sans SC 16 CJK 子集字体，但播放器标签仍沿用原 Montserrat 字体；完整中文显示/字体回退尚需单独接入，且该 CJK 子集不覆盖所有生僻字。

## 内存及文件大小约束

| 对象 | 策略 / 上限 |
| --- | --- |
| 歌曲索引 | 写入 SD `.hmcache/music.idx`，1024 字节/首；RAM 不保存完整歌曲库 |
| 索引文件 | 最大 64 MiB，即最多 65,536 首；超限明确提示，不无限增长 |
| 歌曲列表 UI | 每首创建真实条目，沿用原有布局；后台每批 8 首传输歌名。UI 对象和标签内存随歌曲数量增长，不代表 65,536 首都能同时建出控件。 |
| JPEG 输入 | 当前歌曲优先，相邻歌曲逐张预读；同时仅一个输入，最大 256 KiB，解码后立即释放压缩数据 |
| JPEG 输出 | 四个固定的 240×240×2 字节缓存槽，像素共 450 KiB；另计驱动分配对齐开销。用于当前/相邻封面及动画或解码中的缓冲，不随曲库大小增长 |
| 模糊背景输出 | 三个固定的 460×460 RGB565 槽，共约 1.21 MiB PSRAM；当前底图、淡入图和最新待显示/生成图独立引用，正在显示的槽不能被覆写 |
| 模糊背景工作区 | 两张 80×80 RGB888 小图，共 37.5 KiB PSRAM，初始化时分配并复用；背景输出和工作区合计 1,308,000 字节（约 1.25 MiB），另计元数据/控件开销 |
| LRC 输入 | 文件大小最大 256 KiB；逐行读取，不整文件加载 |
| LRC 索引/文字 | 最多 1024 条，文字 arena 最多 64 KiB；超限停止收录并提示 `limited` |
| 单行歌词 | 文本含终止符最多 512 字节；超长行跳过并标记受限 |
| 歌词 UI | 当前歌曲单个透明 label，副本文字最多 64 KiB；另有同上限的 worker 中转缓冲。歌词切歌动画额外持有一份最多 64 KiB 的滑出快照，动画结束清空。多时间标签展开超限时仅显示完整的前段歌词。 |
| 音频文件 | 不按文件大小分配内存；仅固定大小文件头读取，立即关闭 |

此表不包括 LVGL 页面对象、文件系统内部结构、JPEG 驱动和任务栈等固定开销，不能当作系统总 RAM 测量。
索引每次挂载/重新扫描都重建，不信任旧索引；需要 SD 卡可写并有足够空间。
扫描不修改或删除用户音频/图片/歌词文件。索引创建失败会显示错误，而不是继续使用旧卡的缓存。

FLAC 读取 STREAMINFO，保留原始采样率、声道数、位宽、36 位采样总数，时间/大小使用 64 位计算；
不会把 32-bit / 192-kHz 文件强制当成 16-bit / 44.1-kHz，也不会以文件体积作为缓冲区分配大小。
MP3 当前只确认文件可读，时长显示未知，不使用固定码率估算。
**这些是文件访问/元数据能力，不是对 32-bit / 192-kHz 实时解码和播放能力的承诺。**
下一阶段接解码和 DAC 时仍需核实解码器格式上限、PCM 格式转换、采样时钟和输出吞吐。

## 并发与生命周期

- 单个 `sd_music` 任务负责所有音乐文件访问；LVGL 回调只投递请求，不做 SD I/O。
- 选歌使用单个最新索引请求槽，快速连续点击合并，不建立无限队列；同一首可重复请求。
- 请求序号、卡挂载代次和当前歌曲索引共同拒绝过时加载结果；发布持有 LVGL 锁，动画完成不依赖媒体完成通知。封面先于音频头/LRC 独立发布。
- SD 文件访问锁覆盖打开到关闭；卸载等待文件操作结束；扫描过程中检测物理拔卡退出。
- 工作任务在取得 LVGL 锁后才更新对象；不在 LVGL 任务里等待 SD 文件访问锁。
- JPEG 缓存键为挂载代次和歌曲索引，以 LRU 复用未被持有的槽；短临界区只保护槽元数据，不做文件访问、内存分配或解码。
- UI 当前层、滑出层和 worker 各自持有封面引用；滑出结束先隐藏旧层再释放引用，绝不覆盖动画中的旧图片。重扫/拔卡使缓存键失效，仍被显示层持有的像素继续受保护。
- 每张预读前检查是否出现新选歌；新请求最多等待一张已经开始的封面读取/解码结束，随后优先加载目标，不继续预读剩余邻居。UI 切歌动画始终独立进行。
- 保留原有必要的分配结果检查：初始化失败返回错误，单张封面失败留空，不增加同步加载或备用解码器等额外回退链。

## 封面模糊背景

`main/music_background.[ch]` 在 SD 媒体 worker 中复用已解码的 240×240 原生 RGB565 封面：3×3 面积平均缩至 80×80，三轮水平/垂直滑动窗口盒式模糊近似高斯效果，再以固定点双线性插值放大至 460×460，并将白色遮罩混合烘焙到 RGB565 像素中。边缘复制避免黑边。原始封面不修改、不重复解码，不增加任何 SD 读取；UI 不逐帧缩放、模糊或绘制白色遮罩。

生成时不持有 SD/LVGL/缓存锁；当前歌曲封面、音频信息和歌词先发布，背景随后生成，再处理相邻清晰封面的预读。缓存以挂载代次和歌曲索引为键，只有未被引用的槽才能复用。反复选择已缓存歌曲直接复用背景；只生成当前歌曲的背景，不为整个曲库分配背景。

UI 使用固定在页面最底层的两个非交互 Canvas：底图保持完全不透明，顶图从透明淡入，完成后接管底图。快速请求期间不直接替换半透明顶图，而仅保留最新 pending，当前过渡结束再接续，避免跳帧；新选歌会释放旧 pending，给生成任务留出槽位。worker 发布前再次验证请求序号、挂载代次和当前歌曲，旧结果不得覆盖新选择。重建曲库时取消动画并释放所有显示引用。

可调参数位于 `main/music_background.h`：`MUSIC_BACKGROUND_BLUR_RADIUS` 默认 4、`MUSIC_BACKGROUND_BLUR_PASSES` 默认 3、`MUSIC_BACKGROUND_WHITE_OPA` 默认 38/255。背景过渡时长位于 `ui_music_player.c` 的 `BACKGROUND_FADE_MS`，默认 180ms。全屏透明度混合仍增加绘制开销，实际流畅度需上板与双封面滑动同时验证；浅色封面也应检查现有浅色文字的可读性。

## LVGL 界面回归

`tests/ui_host` 使用工程锁定的 LVGL 9.4.0 和实际播放器/全局手势 C 代码，模拟显示器和触摸输入；SD 后端和其他模式面板用 stub 隔离。需要先由 ESP-IDF 配置下载依赖，再用本机 C 编译器运行：

```powershell
cmake -S tests/ui_host -B build/ui-host -G Ninja -DCMAKE_C_COMPILER="你的本机 GCC 路径/gcc.exe"
cmake --build build/ui-host
ctest --test-dir build/ui-host --output-on-failure
```

`player_ui` 覆盖全屏背景层级/非交互、移动后触摸区域/按键扩展区不重叠/进度与时长间距、旧底图保持不透明的交叉淡变、pending 替换与释放、过时背景拒绝、过渡中重扫清理、封面/歌词分段淡变、淡出与淡入期间连续点击反向、歌词滚动位置保留、缺封面/迟到封面、切歌/重建曲库取消淡变、短标题居中、真实列表行、缓存命中时双封面同时滑动及独立持有、未命中立即切歌和迟到封面补显、重复切歌/重扫取消、歌词快照、首末行/换行歌词居中、按住不回跟及释放后两秒回跟、真实指针横滑不触发点击、歌词拖动不打开列表、其他区域列表展开/上边缘收起。

`player_background` 编译实际背景生成/缓存代码：验证 RGB565 颜色与白色混合、棋盘格模糊、双线性过渡/边缘无黑边、原封面不变、缓存命中、100 次生成无额外分配、持有槽不被复用、挂载代次隔离和清理。使用带越界哨兵的主机分配器，仍不替代实机多核并发验证。

`player_adapter` 编译实际后端调度代码，替换 SD/JPEG/UI/任务接口；覆盖当前歌曲优先、封面先于音频/LRC 发布、前景先于背景处理且生成期间不持有 SD/LVGL 锁、背景缓存命中、背景生成中切歌/换卡的旧结果拒绝、缺封面不生成背景、相邻缓存复用、解码中选歌的过时结果拒绝、预读中选歌停止后续预读、一首/两首曲库和挂载代次变化。此测试为确定性的调用交错，不等同于实机多核并发验证。固件编译通过仍需实机验证 SD/JPEG、实际触摸和长时间运行内存。
