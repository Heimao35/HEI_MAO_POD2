# 长按电源键关机与持久化设计草案

日期：2026-10-18。目标：ESP32-P4，ESP-IDF v5.5.4，AXP2101。

**本文件仅记录调研和建议，尚未实现长按关机、NVS 写入、EEPROM 驱动或新增关机 UI。** 音量键/锁屏代码已在 `4f96b05` 提交；下一轮先与用户确认本草案的交互和存储选择。

## 当前工程事实

- `pmic_axp2101.c` 是 PMIC I2C/IRQ 的唯一消费者；当前 IRQ 掩码 `D0/F8/18` 处理短按，不处理长按或按下/释放边沿。
- 短按进入锁屏，锁屏再次短按或十秒无人操作后渐灭。锁屏使用保留内存的 Light-sleep，触摸 GPIO6/电源键 GPIO10 唤醒；这是与真正关机不同的路径。
- 当前音乐后端仅加载曲库、封面、歌词和音频元信息，尚无实际 DAC 输出/连续解码。不能用当前 UI 的播放状态冒充已实现的音频停止、静音或断点恢复。
- `partitions.csv` 已有 `nvs`：偏移 `0x9000`、大小 `0x6000`（24 KiB）。当前应用没有接入 `nvs_flash_init`/配置保存，也没有找到独立 EEPROM 驱动或用户确认的 EEPROM 型号、容量和接线。
- 亮度渐灭到零只改变面板实际亮度，用户亮度由 `screen_power` 保存；持久化应保存用户设定，不能保存熄屏过程中的零值。

## 关机事件与硬件边界

依据用户提供的 `DOC/datasheet/axp2101.pdf`，寄存器细节仍以 `docs/PMIC_AXP2101.md` 为维护入口：

| 项目 | 已确认字段 | 下一轮行为建议 |
| --- | --- | --- |
| 长按事件 | 使能 `0x41[2]`，状态 `0x49[2]`，RW1C 清除 | 在原 IRQ 消费者扩展，仅向电源任务投递一次关机请求 |
| 按下/释放 | `0x41/0x49[1:0]` | 只在最终交互确实需要按住计时/松手取消时接入，不增加另一套 PMIC 轮询 |
| 长按事件阈值 | `0x27[5:4]`：1 / 1.5 / 2 / 2.5 秒 | 首先读取板上实际值，不先写死阈值 |
| 硬件按住关机阈值 | `0x27[3:2]`：4 / 6 / 8 / 10 秒 | 先读取并据此决定软件保存时限；不默认按手册出厂值运行 |
| 硬件按住关机策略 | `0x22[1]` 使能，`[0]` 选择关机/重启 | 读取核对；保留硬件兜底，改变策略须单独授权 |
| 软件主动关机 | `0x10[0]`；`[1]` 为重启，不能误置 | 最后一步由 PMIC 任务执行；保持其他配置字段、确保只发关机动作 |

软件收到长按事件不等于硬件长按动作被取消。必须从实际 IRQLEVEL/OFFLEVEL 和策略读值计算可用处理时间，再留余量；不保证一定有固定的四秒/六秒保存窗口。PMIC 已按住开机时是否会马上产生长按事件、关机时一直按住是否会重新开机，也需板上验证。

真正关机会关闭普通电源输出，RTCLDO 保留；不是用 Deep-sleep 假装断电。外接 VBUS 时的软关机保持、充电和再上电行为仍需在本板核对。触摸唤醒只属于锁屏，真正断电后的再开机沿用 PMIC 现有电源键/外部电源策略。

## 推荐的软件关机顺序

建议由单一电源状态机协调，状态可为 `RUNNING -> PREPARING_OFF -> SAVING -> POWERING_OFF`。短按和唤醒路径在关机准备期间不能重新启动锁屏动画或并发进入 Light-sleep；重复长按只合并为同一次请求。

1. 记录关机请求，禁止新的切歌/扫描/解码请求。短暂取得 LVGL 锁捕获用户亮度、音量等状态，随即释放；歌曲路径/位置由媒体 worker 提供一致快照，不在 UI 内读取文件。
2. 沿用亮度渐灭作为视觉反馈，停下 MJPEG/LVGL/DPI；不擅自新增确认页、文字或布局。未来有真实音频后，先在音频任务完成短渐静音、停止输出和解码，保证不在活动 DMA 期间切断 DAC 供电。
3. 请求媒体任务有界停止，关闭打开文件并同步本应用写入的数据，再释放 SD I/O 锁；不要从电源任务强杀正在访问文件的任务，也不要持 LVGL 锁等待 worker。
4. 持久化任务写入最终用户快照，等待成功确认。NVS/EEPROM 写入和等待都在 LVGL 锁外，不与屏幕硬件命令或 SD 操作嵌套持锁。
5. PMIC worker 停止普通监测事务，通过同一 I2C 所有者执行 Soft PWROFF。不要提前关闭 DCDC4/ALDO3 造成仍在运行的外设掉电，也不把 `0x10[1]` 重启当成关机。

所有等待需有界且短于实际硬件强制动作窗口。保存失败、I2C 关机失败和持续长按的最终交互仍待用户决定；实现时应保留诊断并允许重试，不能无声声称数据已保存。硬件强制断电/拔电可能丢失最后一次尚未提交的变更，软件不能靠“关机前再写一次”覆盖这些场景。

## 持久化后端建议

如果“EEPROM”泛指掉电保存，建议优先使用现有 Flash 的 NVS，以小型、低频写入保存播放器设置。ESP-IDF v5.5.4 NVS 已提供磨损均衡和异常掉电恢复机制；无需为此搬动当前应用、字体或 SPIFFS 分区，也不需要复制一套 EEPROM 模拟层。

如果板上实际存在外接 EEPROM，则需用户回来后提供型号、容量、I2C 地址/引脚及 WP 接线。页大小、页写延时、ACK 轮询和寿命以该型号手册为准，不照搬 Flash/NVS 行为。可以将设置快照和“加载/保存/等待完成”接口与后端分离，后续选择其一；当前不写两套后端或预先假定 EEPROM 参数。

建议首版使用现有 `nvs` 分区内独立 namespace。若以后无线配置或写入频率明显增长，再评估独立应用 NVS 分区；当前不修改分区表。初始化异常时也不应照搬“失败即擦除整个 nvs”的演示模式，避免未来连带清除其他配置。

## 建议保存的内容

| 信息 | 保存对象与边界 |
| --- | --- |
| 亮度 | 用户设定的非零亮度；不保存渐灭过程值或实际熄屏值 |
| 音量 | 0..100 设备音量；若要恢复独立静音状态需显式加入快照，并与现有静音行为一致 |
| 最后选择的歌曲 | SD 卡相对目录/音频文件名作为稳定身份；不只保存会随扫描排序变化的列表序号 |
| 播放位置 | 将来由真实音频时间轴提供毫秒位置；FLAC/MP3 恢复通过解码器合法 seek，不把任意字节偏移当成可解码位置 |
| 其他可选设置 | 播放模式、上次使用的页面模式、自动亮度开关；是否首版包含由用户决定 |

使用带格式版本、长度的显式序列化快照，避免把带编译器填充/指针的 C 结构直接写入。对字段和路径长度设上限，不保存封面、歌词或整张曲库。首版数据量可限制在约 1 KiB，RAM 不随歌曲数量增加。

NVS 以一个设置 blob 更新一组相关设置，随后显式 `nvs_commit()`；不假定多个独立 key 的一次 commit 具有数据库式跨 key 事务。更改格式时做版本迁移，数据无效或缺失时采用受控默认值，不启动破坏性全分区擦除。若最终用裸 EEPROM，需按其手册补齐写入完成检查、校验和掉电一致性方案。

开机先加载设置再应用亮度/滑条，SD 扫描完成后在媒体 worker 中分批匹配最后歌曲。无 SD、歌曲已删除或卡已更换时正常显示当前曲库；保留待匹配的稳定身份，不启动大规模常驻目录缓存。是否开机自动续播单独确认；恢复歌曲信息不意味着自动发声。

## 保存节奏与性能

- 平时只更新 RAM 并标记 dirty；滑条拖动/按键连调停止后建议合并 3～5 秒再保存。持续操作时设最小写入间隔，避免每个 VALUE_CHANGED/按键重复都写 Flash。
- 切歌后同样短延迟合并；真实连续播放接入后，进度检查点可从 30～60 秒评估，暂停/有效 seek 后合并保存。实际刷新周期在耐久度与可接受丢失进度之间取舍。
- 正常关机绕过限频，提交最后一份 dirty 快照并等待落盘；没有更改时不重复写。
- NVS 写入放后台不代表 Flash 擦写对显示/PSRAM/音频完全无影响。正常关机可在渐灭、停止媒体活动之后保存；平时自动保存需单独验证连续音频和显示压力，不在 LVGL 锁内执行写入，也不承诺绝对无卡顿。
