# 长按关机与设置持久化：实现及扩展记录

更新：2026-10-18。ESP32-P4 / ESP-IDF v5.5.4。
用户本轮已明确授权关机弹窗、重启及 Flash NVS 保存；没有外接 EEPROM 信息。
本文替代先前仅调研的草案。源代码和硬件实测结论分开记录，不以构建成功代替板上验证。

## 按键行为

- PMIC 初始化以读改写和读回校验，将 `0x27[3:2]` 设为 `11b`（10秒），`0x22[1:0]` 设为 `10b`（使能硬件持续按住断电，非重启）。ONLEVEL、IRQLEVEL、过温保护及无关字段保留。
- IRQ 掩码 `D0/FB/18`：增加按下、释放，保留短按；不使能最大2.5秒的长按IRQ。PMIC worker成功清除捕获的RW1C状态后只投递RAM事件；GPIO ISR仍只通知任务。
- 软件在电源任务就绪后，从新观测到的按下边沿开始计6秒；首次达到阈值显示“正在关机，请选择操作”，有“确认关机”“重启”“取消”三个按钮。20ms电源任务检查阈值；I2C/LVGL繁忙时允许提示有调度延迟。
- 同一次持续按住只弹一次。取消关闭弹窗，不改硬件10秒策略；若继续按住，PMIC仍强制断电。强制路径不依赖LVGL/FreeRTOS正常响应，前提是PMIC初始化已成功设置该策略。
- 熄屏按下先唤醒，松手时消费伴随短按，避免再次熄屏；继续按住到6秒显示弹窗。普通短按沿用锁屏/熄屏逻辑。
- 按住、弹窗和保存期间阻止锁屏超时/Light-sleep。新增弹窗在LVGL top layer独立绘制，不移动原页面；新中文使用现有18号全字库。全部UI修改附有维护注释。
- 首次成功读取/清除PMIC按键IRQ快照只建立基线、不向UI派发；电源任务就绪前也丢弃按键回调。只有就绪后观测到完整的新按下/释放，才允许短按驱动锁屏/熄屏；用于开机的按键和重复的孤立短按均被消费，避免亮屏后立即又熄屏。
- 状态寄存器记录边沿而非实时电平：若长时间I2C失败导致按下/释放合并，或开机初始化前已经按住，软件无法重建准确起点；保守处理为不推测丢失的按住时长。PMIC硬件10秒断电不受此软件限制。

## 正常关机与重启

入口 `main/system_power.c` 是唯一正常关机协调者；UI只投递动作，不等待I/O。

1. 禁用弹窗按钮，停止新的媒体请求。锁屏MJPEG取消后，最多等待2.5秒使已经开始的媒体/JPEG读取完成；不强杀持锁任务。
2. 通过适配器捕获最后选择的目录和音频文件名。即使刚点击下一首、尚未读取元数据，也能在媒体空闲后读磁盘索引得到该曲身份。没有SD时保留之前的身份。
3. 复用300ms亮度渐灭，停LVGL和物理DPI刷新；此处不进入Light-sleep，触摸/短按不能中断保存。显示挂起最多等2秒，失败则返回弹窗。
4. 在LVGL锁内捕获最终设置快照后立即释放锁。在锁外 `nvs_set_blob`、`nvs_commit`，重新打开namespace读回并验证整份快照。屏幕渐灭不修改用户偏好亮度。
5. 确认关机由PMIC唯一I2C worker读改写 `0x10`，只发bit0且清除重启bit1；不提前单独关闭DAC/协处理器电源。重启也由PMIC唯一I2C worker读改写 `0x10`，只发bit1且清除bit0，执行AXP2101整机POWOFF/POWON；不调用P4的 `esp_restart()`，也不把十秒硬件长按策略改成重启。
6. 保存/媒体/显示/断电命令失败，恢复屏幕和媒体，弹窗提示“操作失败，请重试或取消”；不默认为成功。关机/重启命令ACK后800ms若本次程序仍执行，亦按终态动作未生效恢复；重启失败不得退回仅P4的软件重启。尚未被worker领取的超时断电请求会撤销，防止迟到断电。

上述等待不是对“十秒前一定完成保存”的承诺。用户持续按住，PMIC到十秒会中断软件流程。当前音频适配器仍只有元数据，后续真实DAC/解码接入时必须补上静音、停止音频DMA、关闭文件等完成确认，不能只靠目前的元数据暂停。

## NVS 数据格式

使用现有分区 `nvs`（offset `0x9000`, size `0x6000`），namespace `player`，单blob key `settings`；不更改分区表、不增加EEPROM模拟层、不自动擦除NVS。

格式是小端显式序列化：12字节头（`HMP2`、版本1、总长、payload CRC32）+ TLV（1字节ID、2字节长度、字段数据）。整个blob上限1024字节。数据不含指针、C填充或整曲库，常驻内存不随歌曲数量增加。

| 固定ID | 内容 | 约束/恢复行为 |
| --- | --- | --- |
| 1 | 用户亮度 | 5..100，沿用既有最小亮度规则；不保存面板渐灭值 |
| 2 | 音量 | 0..100；沿用既有静音/取消静音的音量逻辑 |
| 3 | 静音开关 | 0/1，与滑条及静音按钮同步 |
| 4 | 自动亮度开关 | 0/1，开机恢复后由GPIO22光感低频接管亮度，详见 `AMBIENT_LIGHT.md` |
| 5 | 最后歌曲目录名 | 相对 `music` 目录，最多255字节UTF-8 |
| 6 | 最后歌曲音频文件名 | 最多255字节UTF-8，与目录一起比较 |

初始化先加载，再创建/刷新UI；扫描成功后worker逐条匹配磁盘索引，每条释放SD锁，不构造第二份全曲库缓存。匹配后先同步UI当前索引，再读取封面/歌词/音频信息。歌曲不存在时正常选择第一首；空曲库及无SD提示沿用原逻辑。**不保存播放进度，不自动播放。**

缺少可选字段用默认值；长度、范围、重复字段、CRC错误或未知主版本不会被当成有效设置。初始化异常保持原NVS，本次禁写并采用默认值；后续需要显式迁移/恢复流程。不存在settings key才视作首次使用。正常保存失败不更新已保存快照，允许重试。

## 保存节奏和扩展方法

- 100ms采集RAM变化；停止调整3秒后合并提交，内容与已提交快照相同则不写。正常关机/重启绕过延迟，等待最终保存。写Flash期间公布电源活动，禁止与Light-sleep重叠。
- 强制关机、崩溃和突然拔电只能恢复最近一次完成提交的设置，可能丢失尚未保存的修改。后台写入不等于保证连续音频/显示绝对无抖动；后续真实音频接入需板上测量。
- 增加字段时修改 `player_settings_t`、`encode/decode`、UI/RAM快照的取值和恢复，以及 `player_settings_equal()`；分配新ID，不重用已有ID含义。可选同版本字段可跳过未知ID，不兼容变化必须升级主版本并编写迁移。旧固件重写快照不会保留它不认识的字段，需在版本策略中考虑降级。
- 不直接向NVS写入 `sizeof(struct)`。增加路径或大数据前重新检查1KiB上限；歌词/封面和全曲库不能放入这个设置blob。
- 将来若确有外接EEPROM，先取得型号、容量、I2C地址、接线和WP信息，再选择单一存储后端；当前不预设该硬件存在。

## 首次睡眠/开机按键修正（2026-10-18）

- 本机IDF v5.5.4的 `sleep_modes.rst` External Wakeup (ext1) 明确要求Light-sleep返回后先调用 `rtc_gpio_hold_dis`，再恢复数字GPIO。原实现只有 `rtc_gpio_deinit`，缺少HOLD解除；当前在每次睡眠返回（含拒绝进入的清理路径）对GPIO6/10先解除HOLD，再deinit。
- 原行为可能使GPIO6数字输入被误判为低而立即亮屏，也可能使GPIO10无法交给原数字下降沿IRQ，按键退化到5秒PMIC轮询。代码缺失已确认；是否完全解释用户板上现象仍需同板验证。
- 主机睡眠模型现在模拟RTC pad HOLD，要求解除后才能deinit，验证定时器唤醒不误亮屏，触摸/PMIC路径恢复原GPIO。PMIC模型验证首次旧按键清理、后续边沿交付、整机重启只写0x10[1]且保留十秒强制断电策略。

## 触摸候选与主动唤醒分离（2026-10-18）

- `screen_power_request_wake()` 现在使用独立的主动唤醒事件；PWRON熄屏按下及关机失败恢复不会被触摸数据校验阻止。普通触摸IRQ/RTC唤醒只排队候选，必须新读CST820得到有效触点才亮屏。继续保留唤醒触摸消费到松手的行为。
- 该分离同时适用于渐灭中和完全熄屏后；确认关机的显示停止阶段仍完全忽略触摸，不引入额外关机操作或更改PMIC策略。首次睡眠的HOLD清理、NVS流程和十秒强制断电保持。

## 自动亮度持久化补充（2026-10-18）

- `ui_device_state_t.brightness` 表示当前亮屏亮度；`manual_brightness` 单独记录最近手动偏好。字段1继续保存手动偏好，现有blob无需迁移。
- 光感自动变化只改当前亮度，不修改持久化快照，避免光线缓慢变化导致周期性NVS写入。开机/重启先使用保存的手动值，再平滑接管；不保存关机时的瞬时环境光。
- 用户明确关闭自动亮度时保留当前亮度并记录为手动偏好；拖动亮度滑条同样保存手动值并关闭自动模式。模式切换本身仍按原3秒合并逻辑保存。
