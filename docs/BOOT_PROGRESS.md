# 开机提示与阶段进度条

目标：在外部字库挂载/加载前，给用户明确的英文开机反馈。

## 显示与资源

`main/ui/ui_boot.c` 创建 top layer 下的临时全屏黑底覆盖层，显示：

- `Starting...`：固件内置 Montserrat 22；
- 白色阶段进度条：260 × 6 像素，轨道为低不透明度白色；
- 当前阶段英文：固件内置 Montserrat 14。

不依赖 fontfs、SD、封面或 MJPEG，也不新建任务、定时器、动画、图片资源或帧缓冲。
首次 show 和每次阶段更新均在 LVGL 锁内调用 `lv_refr_now()`，在耗时操作开始前
主动提交画面；不会仅创建对象后就等待被主线程持锁阻塞的 LVGL worker 刷新。

## 启动顺序与锁

`app_main()` 在 LCD/触摸/LVGL 初始化后立即显示提示，接着处理 NVS、字库、
正常页面、PMIC、SD、持久动画资源、音频及系统控制初始化。所有耗时硬件/文件
操作保持在原来的锁范围内：SD/动画导入等在 LVGL 锁外，字库解析继续持共同锁。
普通阶段通过 `app_boot_progress()` 短暂取得锁后发布。

新增 `ui_fonts_init_with_progress()` 提供同步字库阶段通知，原 `ui_fonts_init()`
保持兼容。回调在每个文件加载前报告已完成的尝试数，全部处理完后 filename=NULL。
主线程回调已持有 LVGL 锁，不能再阻塞取锁，也不把 font loader 移到其他任务并发
执行。字体初始化后的生命周期、同字号 fallback 和错误降级保持原样。

进度是启动阶段，不能解释为字节百分比或剩余时间。提示不显示数字百分比；
18 号全字库的同步加载期间，英文与进度条会保持原画面数秒，直到进入下一阶段。
没有人为等待“填满”，也没有单个字库内部进度或持续转动动画。

启动期间 LVGL 触摸输入关闭。结束时仅删除临时覆盖层，不清空 active screen 或
整个 top layer，然后恢复输入并消费未释放触摸、重置显示活动时间。MJPEG 的
原有首次重播请求移至提示退出之后，避免第一段动画在覆盖层下面不可见。
后台曲库扫描完成不属于这个同步阶段条的完成条件；正常界面继续显示扫描状态。
