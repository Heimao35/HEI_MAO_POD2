# AXP2101 项目长期记忆与接入记录

核对日期：2026-10-18。目标为 ESP32-P4，32 MB PSRAM / 32 MB Flash，ESP-IDF v5.5.4。
本文件与根目录 `AGENTS.md` 保存跨会话需要读取的项目事实。硬件接线来自用户明确说明，寄存器来自用户提供的原厂手册，软件行为以当前实现和验证为准。

## 硬件和资料

- PMIC：AXP2101。手册：`F:/PROJECT/HEI_MAO_POD_2/DOC/datasheet/axp2101.pdf`，63 页，修订记录最新为 rev 1.4（2022-10-13）。以下页码对应这份文件。
- SDA = GPIO48，SCL = GPIO47，IRQ = GPIO10。
- I2C 七位地址 `0x34`；手册第 18 页的 `0x68/0x69` 已带读写位，不能直接填入 ESP-IDF 的 `device_address`。
- PMIC 使用 I2C1，初始速率 100 kHz；现有触摸屏使用 I2C0，SDA7 / SCL8。
- IRQ 为低有效开漏，手册建议 4.7 kΩ 上拉；SDA/SCL 建议 2.2 kΩ 上拉。上拉电源须匹配 MCU 接口电平；内部上拉不能代替合适的板级外部上拉（第 8～9 页）。
- 用户已将电源按键接在 PWRON。当前已接入电量、VBUS、充电监测、DCDC4 / ALDO3 开机供电，以及短按/按下/释放事件消费。

- 第 28 页建议为实际电池配置匹配模型改善精度，并说明支持自动学习。本轮不写模型、不复位电量计；成功读取不等于完成校准。

## PWRON 按键：当前实现与硬件边界

| 事件 | 中断使能 | 中断状态 |
| --- | --- | --- |
| 按下 / 下降沿 | `0x41[1]` | `0x49[1]` |
| 释放 / 上升沿 | `0x41[0]` | `0x49[0]` |
| 短按 | `0x41[3]` | `0x49[3]` |
| 长按 | `0x41[2]` | `0x49[2]` |

- 上升/下降沿中断默认未使能；PWRON 内部上拉，按键连接 GND（第 8、19、42、44 页）。
- 上述位记录事件，不是独立实时电平。软件可跟踪按下/释放，但开机时已按住、多个边沿合并的情况需单独定义。`0x20` 是开机来源，不是实时按键状态（第 35 页）。
- `0x27[5:4]` 长按事件阈值为 1 / 1.5 / 2 / 2.5 秒；`0x27[3:2]` 关机按压阈值为 4 / 6 / 8 / 10 秒。软件长按事件不取消硬件长按关机（第 20、37 页）。

## 剩余熄屏自唤醒修正（2026-10-18）

- 用户确认其他问题已经修好，但按键熄屏/十秒空闲熄屏均仍会自行亮屏。
- 本轮确认代码尚有无条件触摸亮屏路径：GPIO6低电平、下降沿IRQ以及EXT1记录会直接触发显示恢复，没有读取CST820触点。软件主动唤醒还和原始触摸共用同一个事件位，不能直接给该位统一加校验。
- 当前把业务/PWRON主动唤醒与触摸候选分离；仅在LVGL输入停止的电源任务中，先 `esp_lcd_touch_read_data` 再 `esp_lcd_touch_get_data`，要求有范围内有效触点才恢复显示。ISR、LVGL锁和SD锁内不做该I2C读取；不使用旧坐标缓存。无触点、无效坐标和读取失败都继续黑屏。
- 原100ms固定任务延时改为有超时的任务通知；触摸IRQ和RTC唤醒立即通知电源任务，使其尽快读到尚未抬起的触点。连续候选最多20ms读取一次，被限频的真实脉冲会保留到下一轮，不无声丢弃。持续低电平且没有触点时暂不进入ANY_LOW睡眠，避免反复被同一电平唤醒CPU；不自动开启背光。
- 主机测试在实际screen_power代码中覆盖零触点IRQ/RTC标志、持续低电平、旧缓存、I2C/取点错误、坐标越界，以及随后真实触摸和电源键正常唤醒。用户随后板测反馈“一切正常”（2026-10-18）。这是当前功能验证通过的反馈；空IRQ的电气来源尚未确认，也没有新增功耗或长期可靠性测量。

## 开机按键、首次睡眠与整机重启修正（2026-10-18）

- 用户报告：关机后按PWRON开机会先亮后灭；首次熄屏可能自行唤醒，之后按键延迟。
- 软件确认开机旧IRQ被当成新按键消费的路径；现在首次按键IRQ快照仅清除，不转发，正常监测重试不重置此基线。UI电源任务就绪前的边沿/短按不排队；就绪后短按必须对应新的一次完整按下/释放。
- 软件确认Light-sleep返回漏掉 `rtc_gpio_hold_dis`；IDF v5.5.4要求先解除GPIO6/10的HOLD，再 `rtc_gpio_deinit` 回数字GPIO。当前补齐该顺序，保持原ISR和EXT1唤醒源。
- “重启”现由PMIC所有者任务执行 `0x10[1]`：原厂手册pp.21/32定义为系统POWOFF/POWON并复位相关寄存器。保持高六位且清除关机bit0；关机反向只置bit0、清除bit1。终态命令均在NVS保存/校验之后，不再调用P4软件重启。
- 原UI布局/动画保持，相关状态交接已注释。代码与主机模型验证不能代替本板首次熄屏、反复唤醒和供电轨重启波形测试。

## 本轮关机接入（2026-10-18）

- `0x27[3:2]` 已通过读改写配置为 `11b`（持续按住 10 秒），`0x22[1]` 已置 1，`0x22[0]` 保持 0（PWRON 超过 OFFLEVEL 选择断电而不是重启）。无关位保留；监测重试不反复切换已成功配置的电源输出。
- `0x41[1:0]` 已使能按下/释放边沿，`0x41[3]` 保留短按通知；`0x41[2]` 长按事件仍不使能，因为软件需要按下/释放计算 6 秒提示，10 秒最终动作由 PMIC 硬件独立完成。IRQ 回调只投递 RAM 事件，I2C 仍在 PMIC worker 中执行。
- 软件按下超过 6 秒会显示确认关机/重启/取消弹窗；取消不会改变 PMIC 的 10 秒硬件兜底。即使 LVGL、SD 或应用任务失效，只要 PMIC 已完成配置，持续按住仍可硬件断电。
- 确认关机/重启会停止新的媒体请求，捕获最后歌曲身份、亮度、音量、静音、自动亮度，使用默认 NVS 分区的 `player` 命名空间保存并 `nvs_commit` 后读回校验。NVS 故障不自动擦除分区；歌曲只保存 SD 相对目录名和音频文件名，不保存播放进度。
- 硬件强制断电不等待软件保存，最近一次尚未提交的调整仍可能丢失；这是强制关机路径的预期边界。

## 早期监测接入记录（当前扩展以前节为准）

- `main/pmic_axp2101.c` 在 UI 创建后启动独立 worker，启动即采样。GPIO10 下降沿 ISR 只通知任务，不做 I2C、内存分配、日志或 LVGL 操作。
- 正常状态每 5 秒轮询兜底，I2C 失败后每 2 秒重试，单次传输超时 100 ms；任务通知合并突发中断。IRQ 启动前已经为低电平也能通过首次主动读取处理。
- 单轮最多清理 4 批中断，防止持续 IRQ 占用 CPU。读取 `0x48～0x4A` 后仅对捕获且属于本模块的位写 1 清除，之后再读当前电源状态；事件本身不作为最终插线状态。
- 当前模块是唯一 PMIC IRQ 消费者，将 `0x40/0x41/0x42` 配为 `0xD0/0xF0/0x18`，只开启 SOC、VBUS、电池插拔、充电开始/完成通知。避免出厂默认开启但无人处理的按键/故障通知将 IRQ 持续拉低。
- **这些掩码只改变通知，不改变 PMIC 自身保护、充电算法或硬件按键关机行为。**后续接入按键/故障消费时，需要同步扩展中断掩码和处理逻辑；非归属本模块的状态位不清除。
- `0x18` 仅在 Gauge 关闭时读改写 bit3，保留主电池充电、纽扣电池充电、看门狗原状态。
- 用户已明确授权：在初始化时把 DCDC4 设为 1.8 V 为 DAC 供电，把 ALDO3 设为 3.3 V 为 ESP32-U4WDH 供电。
- 后台任务首次初始化先按字段读改写 `0x85[6:0]=0x64`、`0x94[4:0]=0x1C`，写入后回读确认，再分别设置 `0x80[3]`、`0x90[2]` 开启两路输出并确认回读。已是目标值时跳过写入；其他电源使能位和共享寄存器字段保持不变。
- 已经开启的目标电源不会先关闭再打开；修改其电压会直接调整现有输出设定。若某步失败，不回滚或关闭已经成功配置的通道，下一轮只补齐尚未完成的字段。
- 供电初始化与电量监测独立：供电步骤失败仍尝试读取电量/VBUS，按原 2 秒间隔重试供电；两路全部成功后，普通轮询或电量读取故障不会再次配置或开关它们。
- 成功日志只表示电压字段和使能位回读正确，不代表测得了引脚实际电压、启动时序或负载能力。ALDO3 300 mA 的电流限制仍须实测评估。
- 不写其他电源通道、充电电流/电压、电池模型、Gauge 复位或硬件按键策略。
- 全部 I2C 访问完成后，才获取 LVGL 锁整体发布状态；通信失败使电量未知并清除陈旧的充电标记。状态不变不额外刷新状态栏。
- `ui_device_state_t` 分开保存 `power_valid`、`battery_present`、`battery_pct_valid`、`vbus_present`、`charging`；充电要求电池存在、VBUS good、电流方向为充电且阶段为 0～3。
- UI 初始/未知时显示 `--%`，正常显示真实百分比和电池格数；金色闪电仅表示实际充电，充满后即使 VBUS 存在也隐藏。
- 电池图标从已启用的 LVGL Montserrat 22 调大到 26，保持 38px 状态栏高度、120px 电量容器、触摸区域和操作逻辑；充电保持金色。UI 修改须详细注释。

## 用户实测反馈与软件关机准备（2026-10-18）

- 用户已确认当前 DCDC4、ALDO3 和 RTC 供电均正常。RTC 的具体电压和各通道负载条件未提供，此记录不扩展为峰值电流或无线稳定性验证。
- AXP2101 支持 I2C 软件关机：`0x10[0] Soft PWROFF` 写 1；同寄存器 bit1 是重启，不能混淆（原厂手册第 20、32 页）。真正实现时应保留其他配置位，将该写入作为关机流程最后的 PMIC 命令，不使用普通配置字段的写后回读确认函数。
- PMIC 关机状态保留 RTCLDO，关闭其余常规电源输出（第 19 页）。因此软件关机不等于从电池物理断开全部电路；实际 RTC 继续供电还取决于板上是否由保留的 RTCLDO 供电。
- 若主控供电来自已关闭的输出，主控与其后台任务会掉电，不能再依靠主控 I2C 发下一条命令唤醒自己。
- PWRON 按键按住超过 ONLEVEL 可作为开机来源；VBUS/VBAT 上升沿、IRQ 拉低等开机来源涉及芯片定制配置，不能默认当前板卡支持全部来源，尤其不能未经实测承诺关机后插线一定开机（第 19～20 页）。
- 插着充电线关机后的充电/自动开机表现需要在本板上验证；读取 VBUS good 和接收到 VBUS IRQ 不能证明关机状态的开机策略。
- 锁屏与关机应分别设计。普通锁屏建议保留运行所需电源，仅处理界面、屏幕和交互；更低功耗可进一步评估主控睡眠与有选择的外设断电。PMIC 本身还有 `0x26` 睡眠/唤醒控制，须结合供电映射和唤醒线路设计，不能直接将整机 Soft PWROFF 用作需要继续播放或立即恢复的锁屏（第 20～21、37～38 页）。
- 本轮仅核对能力并记录信息，尚未添加软件关机/PMIC 睡眠接口，未实际执行断电试验。

## 锁屏熄屏、短按电源键与浅睡眠接入（2026-10-18）

- 仅增加 `0x41[3]` POWERON Short PRESS IRQ 使能，IRQ 掩码从 `D0/F0/18` 改为 `D0/F8/18`；对应 `0x49[3]` 在成功 RW1C 后向电源任务投递一次事件（原厂 PDF 第 42、44 页）。不改变按键时长、长按断电策略、充电设置或任何电源通道。
- 现有屏幕触摸为 CST820：I2C0 SDA7/SCL8、RESET GPIO5、低有效 INT GPIO6。原 esp_lvgl_port 的触摸 IRQ 回调和 user_data 保留；熄屏时回调只记录唤醒标志，亮屏正常转交。IRQ 中不执行 I2C、LVGL 或文件操作。
- `main/screen_power.c` 使用 LVGL 的输入活动时间：仅锁屏可见且无人按住屏幕时，满十秒或锁屏亮屏时再次短按电源键，先暂停 LVGL 定时器/输入、取消旧锁屏解码请求，再用 FreeRTOS 时钟推进约 300ms 亮度渐灭，到零后在帧 DMA 完成处停下 DPI 刷新，屏蔽仅用于诊断计数的 GPIO23 TE IRQ。不是只把画面刷成黑色。
- 播放状态保持 CPU 运行；暂停/空闲采用最多约一秒一轮的显式 Light-sleep，轮次之间保留 PMIC 监测和 SD 热插拔处理机会。入睡前必须锁屏 JPEG worker 空闲、PMIC I2C worker 停稳，并在 LVGL 锁外取得 SD I/O 互斥锁。当前音乐后端尚无 DAC/连续解码，`music_player_adapter_is_playing()` 当前报告无真实输出；未来音频接入必须在实际输出整个期间维持准确播放状态。
- P4 GPIO6/GPIO10 都是 RTC GPIO。使用 `esp_sleep_enable_ext1_wakeup_io(..., ESP_EXT1_WAKEUP_ANY_LOW)`，不通过 `gpio_wakeup_enable` 将正常负边沿 IRQ 改为电平 IRQ；每次睡眠返回后 `rtc_gpio_deinit` 交还数字 GPIO。触摸控制器、PMIC、PSRAM 及所需数字外设保持供电，不关闭 DCDC4/ALDO3，不开 HP 外设睡眠掉电。
- PMIC 的 VBUS/SOC/充电中断可唤醒 CPU 进行后台处理，但只有解析出的短按事件才亮屏。触摸 EXT1 唤醒状态也用于捕获已结束的 IRQ 脉冲；唤醒触摸被等待释放逻辑吞掉，不同时触发解锁。恢复使用之前的非零亮度，并从锁屏首帧重播，保留原布局/上滑解锁及侧栏手势；仅从其他页面进入锁屏时使用 `UI_ANIM_DURATION_MS` 与 `UI_ANIM_PATH` 滑入；锁屏熄屏唤醒只重播 MJPEG，不重新滑入，渐灭中触摸/短按也可取消熄屏。
- 锁屏 MJPEG 改成单一常驻 worker，复用原画布和解码 staging buffer；请求代次阻止旧帧写回，新锁屏/唤醒从头播放，熄屏和解锁禁止迟到的开机动画请求重新启动 JPEG。图像发布和 LVGL 绘制共用锁，JPEG/文件读取在锁外。
- IDF v5.5.4 的 DPI 驱动无公开暂停 API，因此工程通过 `scripts/display_sleep.cmake`/`scripts/patch_dpi_sleep.py` 从已安装驱动生成带帧边界暂停握手的编译副本，输出仅在 `build/player_display`。追加实现为 `main/display_dpi_sleep.inc`，与原驱动同一编译单元，不猜测私有结构体 ABI、不修改 SDK 安装目录或 managed_components；版本及替换锚点不匹配则配置阶段报错，升级 SDK 必须复核。
- 官方 API 核对范围：ESP-IDF v5.5.4 Sleep Modes（EXT1、显式 Light-sleep、PSRAM 保持及内部任务栈要求），本机同版本 `sleep_modes.c`、GPIO/RTCIO 与 MIPI-DPI/GDMA 驱动源码。能力不等于本板实测，GPIO 电平/脉宽、重复休眠恢复、DPI 首帧稳定性及整机电流仍需板上验证。


## 锁屏唤醒后显示错位修正（2026-10-18）

- 用户实测：熄屏后可正常唤醒，但显示内容错位。代码中已发现高疑似原因：DMA done 仅代表像素送至显示桥，不代表整帧已经从显示桥/Host 发往面板。原暂停立即关 DPI，随后直接从帧首重启，未清除旧 FIFO 和扫描状态；是否为本板唯一根因仍待实测。
- `display_dpi_sleep.inc` 唤醒时在亮度仍为零、DMA 已停的条件下，保存显示桥时序/颜色/DMA 配置，复位显示桥及 Host，恢复配置，再使用原 `cur_fb_index` 的帧缓冲启动。不重建 LVGL、不新增全屏缓冲、不重置屏幕或 D-PHY，也不操作 PMIC 供电。
- `patch_dpi_sleep.py` 在官方桥中断处理器加入真实 VSYNC 序号。恢复需等两个新 VSYNC 才成功返回并允许亮屏；不将 DMA done 或熄屏前遗留的中断状态作为完成条件。等待超时保持黑屏，并可重试等待，不能对已运行的 DMA 再次复位桥。
- 此实现明确要求 `CONFIG_ESP32P4_REV_MIN_FULL >= 300`（本项目当前为 300）；较早芯片缺少对应桥复位/真实 VSYNC，编译报错，不能悄悄套用。SDK 仍固定 v5.5.4，生成文件仅位于 build，不改已安装 SDK 或 managed_components。
- 主机测试 7/7 通过，含残留 FIFO、配置保存、保留当前帧缓冲、真实 VSYNC 等待、无 VSYNC 超时重试和计数器回绕。固件构建通过，镜像大小 `0x10cad0`；用户随后反馈恢复效果不错；连续长时间熄屏/唤醒稳定性仍需板上验证。

## CS43131音频与共享总线（2026-10-19）

- DAC与PMIC共享现有I2C1（SDA48/SCL47），由音频任务通过`i2c_master_get_bus_handle()`加设备，使用驱动已有的总线事务串行化；不创建新总线、不改变PMIC速率/中断策略或电源电压。
- `pmic_axp2101_outputs_ready()`仅发布已存在的DCDC4/ALDO3配置验证结果，DAC等待它成功后才释放GPIO52复位。该快照不是实际电压/负载测量。
- 播放和输出准备阶段禁止Light-sleep；空闲DAC任务在独立sleep请求下停稳并ACK后才能睡眠。关机通过媒体适配器取得另一独立所有权，不能被屏幕唤醒取消；详情见`CS43131_AUDIO.md`。
