# 环境光传感器与自动亮度

日期：2026-10-18。目标：ESP32-P4，ESP-IDF v5.5.4。

## 硬件与依据

- 用户板上器件：Everlight ALS-PT19-315C/L177/TR8，用户提供手册Rev.8，路径 `F:/PROJECT/HEI_MAO_POD_2/DOC/datasheet/ALS-PT19-315C-L177-TR8_V8.pdf`。
- 用户接法：3.3V → 光电晶体管 → VOUT/GPIO22 → 10kΩ → GND。按该接法，环境越亮，输出电压越高。GPIO22为ADC1通道6，由 `adc_oneshot_io_to_channel()` 查询实际映射。
- 原厂手册第1、3、4页：模拟光电流输出、推荐2.5–5.5V供电；100lx/1000lx的典型光电流分别15µA/150µA，测试条件为VCE=5V、6500K白色荧光灯（量产用白LED替代）。2856K白炽灯1000lx的典型光电流520µA，说明光源光谱影响明显。
- 10k负载下，15µA对应150mV只用于确定调参初始量级。实际3.3V接法的VCE会随输出变化，且有器件离散性、外壳透光率和光源差异；当前不是经标定的lux测量。
- 乐鑫P4数据手册ADC Characteristics的ATTEN3有效范围为0–3300mV，误差表的测试前提包含25°C、DC输入和外接100nF电容。不能将表内误差当作本板保证值；当前软件使用12dB衰减、12bit默认位宽及曲线校准。

## 实现和调参

`main/ambient_light.c`负责ADC初始化、单次读取、十档选择和直线过渡；`screen_power.c`负责在既有显示任务中调度、锁内发布UI、锁外串行写屏幕亮度。

用户实测上一版滤波+连续确认+每秒5个百分点限幅响应迟钝，本版按用户要求移除这些处理，改为直接选档及快速线性过渡。

- 没有新增任务、IRQ、连续ADC或DMA，不每轮申请堆内存，不使用采样数组。
- 仅自动模式且亮屏、无关机/保存活动时读取；手动/熄屏/关机时取消过渡。唤醒沿用上次非零亮度，再读取新数据选档。
- `SAMPLE_PERIOD_MS=100`：每100ms最多一次ADC读取，再做校准得到mV，直接选档。没有异常值剔除、均值、EMA、死区或多次确认。读取/校准失败保持实际亮度、取消旧过渡，下一次成功读取恢复。
- `LEVEL_MV_STEP=75`：根据用户“整体偏暗”的反馈，将电压档距从100mV缩小到75mV；同一电压对应更高亮度，目标仍固定10%、20%……100%。这是可调映射参数，不是传感器满量程，也不宣称其代表固定lux值。减小此值会更亮，增大则更暗；例如改为60会进一步调亮，改为90则比当前稍暗。
- `TRANSITION_MS=250`：每次跨档从屏幕当前值开始，在250ms内按时间直线插值到新档位。同档采样不重启过渡；环境迅速反向变化时立即改向新档位，无需先完成旧过渡。
- 过渡中显示任务约每20ms推进一次，稳定后恢复100ms轮询。中间亮度允许落在档位之间，终点严格为十档之一；稳定后不重复写亮度命令。任务繁忙时按真实经过时间跳过迟到步骤，不补发积压更新；实际完成时间可能因调度略晚于250ms。
- ADC始终最多10次/秒；过渡步仅写小型DCS亮度命令，不增加全屏动画/遮罩。UI滑条采用最多等待1ms的锁内发布，拿不到锁就延后同步最新实际值，硬件渐变不等待UI。

| 传感器电压mV | 目标亮度% |
|---:|---:|
| 0–74 | 10 |
| 75–149 | 20 |
| 150–224 | 30 |
| 225–299 | 40 |
| 300–374 | 50 |
| 375–449 | 60 |
| 450–524 | 70 |
| 525–599 | 80 |
| 600–674 | 90 |
| >=675 | 100 |

调参示例：300mV由原40%提高到50%，600mV由原70%提高到90%；达到100%的门槛由900mV降低到675mV。最低档仍为10%。只修改`LEVEL_MV_STEP`即可整体调整响应曲线，重新编译并烧录后生效。

## UI与持久化

- 不改变原布局、颜色、动画或手势。原A按钮通过独立模式回调通知显示任务；自动调光异步同步原亮度滑条，不发送VALUE_CHANGED事件、不计作用户活动，也不干扰音量控件。
- 原手动拖动继续关闭自动模式并应用手动亮度。用户点击关闭自动模式时保留当前可见亮度，记作新的手动偏好。
- `brightness` 表示当前亮屏值；新增 `manual_brightness` 表示手动偏好。NVS字段1仍保存手动偏好，字段4仍保存自动模式，不改变blob版本/字段布局。
- 自动光照变化不改变NVS快照，避免不停写Flash；开机先恢复手动值，再平滑接管。现有初始化后的3秒合并保存/关机最终保存规则保留。
- ADC未能初始化/校准时记录启动警告并保留手动亮度，自动模式开关不被悄悄覆盖；采样失败首次告警、恢复后允许记录下一次故障。不影响播放器启动，也不绕过当前睡眠/唤醒逻辑。

## 验证边界

- ESP-IDF v5.5.4固件构建通过；主机CTest 11/11通过。
- 运行真实采样/直线过渡及显示电源代码，使用硬件替身覆盖LVGL持续占锁超过250ms时硬件中间值连续输出、延期发布不覆盖手动命令，以及十档边界、单次读取间隔、同档不重启、快速光照反向、ADC/校准失败保持值、计时回绕、最终UI发布重试、熄屏/电源活动暂停、锁外ADC访问、采样期间手动覆盖、真实LVGL滑条事件以及自动变化不写NVS。
- 尚未进行本板光照/光路标定，不能宣称曲线观感、绝对照度精度或功耗已实测。建议分别在遮挡、室内、强光下观察稳定性，检查锁屏10秒熄屏与触摸/电源键唤醒；反馈偏亮/偏暗或反应速度后只需调曲线和控制参数。

## 渐变突变修正（2026-10-18）

- 用户板测反馈十档版本仍表现为突然变化。代码发现旧路径在采样前、发布建议值前都要取得LVGL锁，再将亮度写给屏幕。绘制繁忙超过过渡时长时，中间值会被丢弃，解锁后按已经过去的时间直接写终点。这是已确认的代码缺陷及可复现的失效路径；没有串口时序/波形记录，不能断言其为本板唯一原因。
- `screen_power_set_auto_brightness()`由原A按钮回调投递模式；模式、手动亮度及命令代次在极短临界区内交接。不在临界区或LVGL锁内执行ADC/DCS。
- 显示任务直接按模式快照采样/推进过渡，以成功写入的`s_panel_brightness`作为物理起点，不使用可能滞后的UI值。采样后复核代次，手动拖动/模式切换立即使旧自动结果失效。
- 硬件写入在锁外完成，UI只作为观察者：最多等1ms，失败保留dirty，解锁后只同步最新实际值。渐变期间锁屏超时检查同样最多等1ms，避免其原50ms等待拖慢硬件步进。
- 修正保留用户已在源码中改成的100mV档距，250ms线性过渡及100ms采样间隔不变。没有恢复EMA/异常值剔除等滤波，没有修改原布局/手势/动画。
- 新测试用屏幕驱动替身记录实际亮度命令，模拟LVGL占锁超过250ms，要求仍连续收到中间值；解锁后滑条同步最新值，手动请求优先。采样插值数学另由真实模块测试覆盖。最终显示观感仍需本板复测。

## 板测反馈与整体调亮（2026-10-18）

- 用户确认解耦LVGL后的自动调节渐变效果良好，但整体偏暗。本次只将档距从100mV改为75mV，保留100ms采样、250ms线性过渡及20ms推进，不引入额外滤波或UI变化。
- 75mV映射的实际观感仍待本板验证；此前渐变修复已获用户实测认可。
