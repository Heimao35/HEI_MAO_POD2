## 1. 系统概览（已定事实）

| 角色 | 器件 | 说明 |
| --- | --- | --- |
| 主控 | **ESP32-P4NRW32（芯片版本 v3.2）** | 跑 UI（LVGL）、音频解码、文件系统、蓝牙 Host 协议栈 |
| 协处理器 | **ESP32-U4WDH** | 提供 WiFi + BT Classic(BR/EDR) + BLE；只跑控制器与射频，经 **ESP-Hosted over SDIO 4-bit** 与主控通信 |
| 显示 | CO5300 AMOLED 460×460 | MIPI-DSI 1-lane（专用 PHY 引脚，不占 GPIO） |
| 触摸 | CST820 | I2C-0；驱动已在 `components/esp_lcd_touch_cst820/` |
| 音频 | CS43131 DAC（自带晶振） | I2S 从主控接收数据，I2C-1 控制；耳放/输出级待定 |
| 存储 | microSD（SDMMC Slot0，4-bit） | 曲库与文件系统 |
| 电源 | AXP2101 PMIC | 充电、多路电源、电量计、电源键（PWRON）+ IRQ 上报 |
| 传感 | BMI270（IMU）、ALS-PT19-315C（环境光，ADC） | 用途待规划 |
| 时钟 | PCF85063TP（RTC） | ⚠ 无闹钟/定时器，见 §5 |
| 交互 | 3 按键（音量 A=BOOT/GPIO35、音量 B、电源键走 PMIC） | |

**代码基线**：当前 `main/main.c` 仍是 CO5300 + CST820 + LVGL 的示例工程，尚无产品功能代码。

**构建环境**：ESP-IDF **5.5.4**（P4 v3.x 要求 ≥5.5.3），target `esp32p4`；PSRAM 已启用（200 MHz，XIP from PSRAM）；LVGL 9 + esp_lvgl_port。

## 4. 已确定的关键约束（由硬件推导，设计时不可违反）

1. **蓝牙协议栈跑在主控（P4）上**：ESP32 协处理器只做控制器/射频，HCI 经 SDIO 的 VHCI 转发。经典蓝牙（A2DP 等）**只有 ESP32 能做协处理器**，这也是选 U4WDH 的原因。
2. **音频解码必须由主控完成**（SBC/AAC 等），音频数据经 I2S 出到 CS43131；DAC 自带晶振，主控**不输出 MCLK**。
3. **协处理器没有引脚 JTAG**：ESP32 侧的调试/烧录只能靠其 UART 测试点；主控侧调试走 USB-Serial/JTAG（GPIO24/25 必须保留）。
4. **存储与协处理器链路并行工作**：SD 卡走 SDMMC Slot0、协处理器走 Slot1，两 Slot 共享 SDMMC 驱动，注意官方组合示例的配置要求。
5. **深睡唤醒源非常有限**：LP 域（可唤醒深睡的引脚）只剩 **GPIO13** 与 GPIO0–GPIO2；已占用的唤醒源为 AXP2101 IRQ（GPIO10）、触摸 INT（GPIO6）、IMU INT（GPIO12）、CARD_DET（GPIO9）。
6. **RTC 没有闹钟**（PCF85063TP）→ 定时唤醒只能用主控自身 RTC 定时器，或换 PCF85063A（见 §5）。
7. **环境光只有一路 ADC**（GPIO22），且分压满量程点需按手册核算。
8. **芯片版本已锁定 v3.x**：`sdkconfig` 与 `sdkconfig.defaults` 已设为 `CONFIG_ESP32P4_SELECTS_REV_LESS_V3=n` + `CONFIG_ESP32P4_REV_MIN_300=y`（最低 v3.0，可跑 v3.0 / v3.1 / v3.2）。
   ⚠ **v3.x 与 <v3.x 的固件镜像互不兼容**：本工程产出的固件烧不进 v3.0 以前的芯片，反之亦然。若产品线会混用两种芯片，必须分别构建两套镜像。
   此设置同时决定了 GPIO32/GPIO33 的 strapping 判定按 v3 处理（见引脚文档 §3）。

## 5. 待决策清单

| # | 事项 | 影响 |
| --- | --- | --- |
| 1 | RTC：换 **PCF85063A**（有闹钟，但封装不同需改板）还是保留 TP（无闹钟，定时唤醒交给主控） | 投板前必须定 |
